# nonsul-review v0.1.0 (pre-release)

수리논술 강사용 판정 초안·검수·평가 CLI의 첫 사전 공개 버전입니다. 이 문서는 게시에 사용할 릴리스 노트이며, 문서의 존재 자체가 GitHub Release 게시 완료를 뜻하지 않습니다. PyPI에는 이 작업으로 배포하지 않습니다.

## 포함 기능

- 문항 YAML과 Markdown/LaTeX 답안의 엄격한 형식·ID 연결 검증
- 같은 원래 정보와 설정을 사용하는 루브릭 방식·자유형 방식
- 항목별 판정·실제 답안 인용·이유·피드백과 단계별 API 원본 기록
- 단일/배치 실행, dev/test 선택, 기존 결과 보존
- 강사 검수 YAML, 수정 후 확정, 변경 기록
- 최초 채점 일치도·가중 Cohen κ, 오류 탐지, 대안 풀이 오판 지적과 평가 포함률
- 공개 자체 작성 예제와 명시적인 오프라인 데모 모드
- 설치 가능한 wheel/sdist와 CI·수동 게시 절차

### 검수 절차 v2

`run`·`batch`·`live_smoke.py`의 기본 절차는 v2입니다. 학생용 피드백과 강사용 이유를 구분하고, 정확한 원문 인용의 수식 경계와 보완 설명의 검산을 지시합니다. 두 방식의 마지막 단계는 `review_flags`를 반드시 반환합니다. 플래그는 해당 항목의 `needs_review`를 켜지만 판정값과 이유를 자동 변경하지 않습니다. 검수 YAML과 `finalize`에서도 플래그 및 검토 확정 기록을 보존합니다.

API 호출 수는 그대로입니다. v1 프롬프트와 이전 결과의 검수·확정을 지원하며, Python `RunConfig`의 기본값은 호환성을 위해 v1을 유지합니다. [v2 설계 문서](review-procedure-v2.md)를 참고하세요.

## dev 검증 요약

공개 두 문항과 비공개 두 문항의 원래 답안 12개를 두 방식으로 실행했습니다. 문항마다 루브릭은 4항목으로, 총 96개 판정을 작성자 기준과 비교했습니다. 비공개 자료의 본문·인용·결과·raw는 공개하지 않고 집계만 기록합니다.

| 검증 묶음 | 판정 일치 | 해석 |
| --- | --- | --- |
| v1, 원래 입력 | 94/96 (97.9%) | 불일치 2건은 한 답안의 같은 항목에서 두 방식에 공통으로 나타난 기준 해석 차이 |
| v2, 같은 원래 입력 | 94/96 (97.9%) | 판정 일치도는 같았고 피드백과 검토 필요 표시에서 차이가 관찰됨 |
| v2, 개정 루브릭·개정 답안 | 32/32 | 자료 개정의 작동 확인. 원래 입력의 비교 수치와 합산하지 않음 |

v1에서 확인한 명시적인 수학 오류 2건은 원래 입력의 v2 실행에서 다시 관찰되지 않았습니다. 학생용 문장의 채점 용어·강사 메모와 인용의 수식 경계도 개선됐습니다. 원래 입력의 v2에는 타당한 검토 플래그 4건이 있었으며, 구조적으로 `needs_review`에 반영됐습니다.

다만 원래 입력의 v2에서도 하한과 유일성을 충분히 구분하지 않은 종합 설명, 조건을 생략한 보완 설명, 핵심 근거 누락을 지적하지 못한 사례가 남았습니다. 개정 자료 실행에서는 문제였던 항목이 의도한 `partial`로 판정됐고, 추가한 핵심 근거도 두 방식이 인정했습니다. 과거 결과는 보존하며 새 결과로 덮어쓰지 않습니다.

이 자료는 개발 중 개선에 사용한 소규모 dev 세트입니다. 독립 평가자가 확정한 평가셋이나 실제 학습자 표본의 본 비교 평가가 아닙니다. 같은 원래 입력의 두 방식은 판정 일치도가 같았으며, 특정 방식의 우월성이나 프롬프트 변경의 일반적인 인과 효과를 입증하지 않습니다. 피드백의 수학적 문제·내부 모순·불필요한 보완 요구는 dev에서 도출한 탐색 항목입니다.

## 배포 검증과 게시

- [v2 구현 커밋의 CI](https://github.com/dokim111/nonsul-review/actions/runs/36540313464)가 통과했습니다.
- 같은 v2 소스의 로컬 테스트 192개, lint·format, wheel/sdist 빌드와 twine 검사를 통과했습니다.
- 공개 증거에 대해 `release_check.py --require-live`와 원본 응답 대조를 통과했습니다.
- 문서·증거를 포함한 최종 커밋의 CI와 `--dist dist --require-live --require-tracked` 검사를 확인한 뒤 태그·수동 게시 워크플로로 진행합니다. 게시 워크플로도 해당 태그의 CI·빌드·증거 검사를 다시 수행합니다.

절차는 [릴리스 안내](releasing.md)를 따릅니다. CI와 Release의 실제 상태는 [Actions](https://github.com/dokim111/nonsul-review/actions)와 [Releases](https://github.com/dokim111/nonsul-review/releases)에서 확인합니다.

## 설치·시작 및 한계

wheel을 설치하거나 소스를 받아 `python -m pip install .`로 설치합니다. Python 3.10 이상이 필요합니다. 소스 README에는 API 키 없이 실행하는 데모와 실제 API 설정, 강사 검수·확정·평가 예제가 있습니다.

모델 출력은 강사 검수 전 초안입니다. 플래그가 없어도 오류가 없다는 뜻은 아니며, 학생에게 전달하기 전에 강사가 확인해야 합니다. 판정 불가 항목은 `null`과 검수 필요 표시로 남고, 강사가 판정한 뒤 확정합니다. 현재 버전은 이미지·손글씨 인식이나 학생용 앱을 제공하지 않습니다.

이 GitHub pre-release는 PyPI 업로드를 자동으로 수행하지 않습니다. `pip install nonsul-review`는 PyPI 게시를 따로 확인한 뒤 사용합니다. GitHub의 pre-release 표시와 Python 패키지 버전 `0.1.0`의 의미는 별도입니다.
